#### 環境変数の追加方法

各環境変数を1つずつ追加:

2. **Value**: 対応する値をコピペ
3. **Environments**: `Production`, `Preview`, `Development` 全てにチェック
4. 「Save」をクリック

4. **再デプロイ**
   - Deployments タブに移動
   - 最新のデプロイの右側の「...」メニューをクリック
   - 「Redeploy」を選択

### Option 2: デプロイ時に環境変数を設定

もし新規プロジェクトを作成し直す場合:

1. **プロジェクト作成画面**で「Environment Variables」セクションを展開
2. 上記の環境変数を全て追加
3. Deployをクリック

## ⚠️ 重要な注意点

### Root Directoryの設定確認

プロジェクト設定で以下を確認してください:

- **Webアプリ**: Root Directory = `web`
- **Adminアプリ**: Root Directory = `admin`

確認方法:
1. Settings → General
2. 「Root Directory」セクションを確認
3. 間違っている場合は「Edit」で修正

---

## 📝 環境変数の説明

| 環境変数 | 説明 | 必須 |
|---------|------|------|
| `NEXT_PUBLIC_SUPABASE_URL` | SupabaseプロジェクトのURL | ✅ |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase公開キー | ✅ |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabaseサービスロールキー（サーバー側のみ） | ✅ |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Google Gemini APIキー | ✅ |
| `REVALIDATE_SECRET` | キャッシュ無効化用シークレット | ✅ |
| `ADMIN_URL` | AdminアプリのURL | ✅ |
| `CHAT_DAILY_COST_LIMIT_USD` | AI Chatの日次コストリミット | オプション |

## 🔄 再デプロイ後の確認

環境変数を追加して再デプロイした後:

1. **ビルドログを確認**
   - Deploymentsタブで進行状況を確認
   - エラーがないか確認

2. **デプロイ成功後**
   - アプリのURLにアクセス
   - 正常に表示されるか確認

## 💡 トラブルシューティング

### まだエラーが出る場合

1. **環境変数のタイポ確認**
   - キー名が完全に一致しているか
   - 値に余分なスペースがないか

2. **適用範囲の確認**
   - Production, Preview, Development全てにチェックが入っているか

3. **再デプロイの実行**
   - 環境変数を追加しただけでは反映されない
   - 必ず「Redeploy」を実行

4. **ビルドコマンドの確認**
   - Settings → General → Build & Development Settings
   - Build Commandが空欄でOK（vercel.jsonで設定済み）
