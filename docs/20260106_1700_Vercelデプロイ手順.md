# Vercelデプロイ手順

## 概要
miraigikaiシステムをVercelにデプロイするための手順書です。このプロジェクトは2つのNext.jsアプリケーション（web/admin）とSupabaseを使用しています。

## 前提条件

### 1. Supabaseプロジェクトのセットアップ
ローカル開発環境とは別に、プロダクション用のSupabaseプロジェクトが必要です。

1. [Supabase Dashboard](https://supabase.com/dashboard) でプロジェクトを作成
2. プロジェクト設定から以下の情報を取得:
   - Project URL (例: `https://xxxxx.supabase.co`)
   - `anon` public key
   - `service_role` key (Settings → API)

3. マイグレーションの適用:
```bash
# ローカルのマイグレーションファイルをプロダクションに適用
npx supabase link --project-ref <your-project-ref>
npx supabase db push
```

### 2. Vercelアカウント
- [Vercel](https://vercel.com) でアカウントを作成
- GitHubリポジトリと連携（推奨）

## デプロイ構成

### プロジェクト構成
このモノレポには2つのNext.jsアプリがあります:
- `web/` - 公開用アプリケーション
- `admin/` - 管理用アプリケーション

Vercelでは**2つの別々のプロジェクト**として設定します。

## デプロイ手順

### Step 1: Gitリポジトリの準備

1. `.gitignore` に以下が含まれていることを確認:
```
.env
.env.local
node_modules/
.next/
```

2. コードをGitHubにプッシュ:
```bash
git add .
git commit -m "Vercelデプロイ準備"
git push origin main
```

### Step 2: Web アプリのデプロイ

1. Vercel Dashboardで「Add New Project」
2. GitHubリポジトリを選択
3. プロジェクト設定:
   - **Framework Preset**: Next.js
   - **Root Directory**: `web`
   - **Build Command**: `cd .. && pnpm install && cd web && pnpm build`
   - **Output Directory**: `.next`
   - **Install Command**: `pnpm install`

4. 環境変数を設定（Settings → Environment Variables）:

```bash
# Supabase設定（プロダクション）
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# AI設定
GOOGLE_GENERATIVE_AI_API_KEY=your-gemini-api-key
AI_GATEWAY_API_KEY=your-ai-gateway-key

# Langfuse設定（オプション）
LANGFUSE_PUBLIC_KEY=your-langfuse-public-key
LANGFUSE_SECRET_KEY=your-langfuse-secret-key
LANGFUSE_BASE_URL=https://cloud.langfuse.com

# その他
REVALIDATE_SECRET=your-secret-key-here
ADMIN_URL=https://your-admin-app.vercel.app
CHAT_DAILY_COST_LIMIT_USD=10

# Basic認証（必要な場合）
BASIC_AUTH_USER=your-username
BASIC_AUTH_PASSWORD=your-password
```

5. 「Deploy」をクリック

### Step 3: Admin アプリのデプロイ

1. Vercel Dashboardで「Add New Project」
2. 同じGitHubリポジトリを選択
3. プロジェクト設定:
   - **Framework Preset**: Next.js
   - **Root Directory**: `admin`
   - **Build Command**: `cd .. && pnpm install && cd admin && pnpm build`
   - **Output Directory**: `.next`
   - **Install Command**: `pnpm install`

4. 環境変数を設定:

```bash
# Supabase設定（プロダクション）
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# Web URL
NEXT_PUBLIC_WEB_URL=https://your-web-app.vercel.app
```

5. 「Deploy」をクリック

### Step 4: vercel.json の更新

デプロイを有効化するため、両方のアプリの `vercel.json` を更新:

**web/vercel.json**:
```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "git": {
    "deploymentEnabled": true
  },
  "buildCommand": "cd .. && pnpm install && cd web && pnpm build",
  "installCommand": "pnpm install"
}
```

**admin/vercel.json**:
```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "git": {
    "deploymentEnabled": true
  },
  "buildCommand": "cd .. && pnpm install && cd admin && pnpm build",
  "installCommand": "pnpm install"
}
```

### Step 5: 環境変数の相互参照を更新

デプロイ後、実際のURLで環境変数を更新:

1. **Web アプリ**の環境変数:
   - `ADMIN_URL` を Admin アプリの実際のURL（例: `https://mirai-gikai-admin.vercel.app`）に更新

2. **Admin アプリ**の環境変数:
   - `NEXT_PUBLIC_WEB_URL` を Web アプリの実際のURL（例: `https://mirai-gikai.vercel.app`）に更新

3. 両方のアプリを再デプロイ（環境変数変更後は自動的に再デプロイされます）

## トラブルシューティング

### ビルドエラー: "Cannot find module"
- モノレポの依存関係が正しくインストールされていない可能性があります
- Build Command を `cd .. && pnpm install && cd <app> && pnpm build` に設定してください

### 環境変数が反映されない
- Vercel Dashboard で環境変数を設定後、再デプロイが必要です
- Production/Preview/Development の適用範囲を確認してください

### Supabase接続エラー
- プロダクション用のSupabase URLとキーが正しく設定されているか確認
- Supabaseプロジェクトのマイグレーションが適用されているか確認

### pnpm関連のエラー
- Vercelは自動的にpnpmを検出しますが、`pnpm-lock.yaml` がリポジトリに含まれているか確認してください

## カスタムドメインの設定（オプション）

1. Vercel Dashboard → Settings → Domains
2. カスタムドメインを追加
3. DNSレコードを設定（Vercelが指示を表示）

## 継続的デプロイ

GitHubリポジトリにプッシュすると、Vercelが自動的にデプロイします:
- `main` ブランチ → Production
- その他のブランチ → Preview

## セキュリティチェックリスト

- [ ] `.env` ファイルが `.gitignore` に含まれている
- [ ] プロダクション用のSupabaseキーを使用
- [ ] `REVALIDATE_SECRET` を強力なランダム文字列に設定
- [ ] Basic認証が必要な場合は設定
- [ ] Supabase Row Level Security (RLS) が有効
- [ ] API Keyが環境変数として安全に管理されている
